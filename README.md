# Agentic RAG Benchmark

**Comparison of BM25 · Vector (FAISS) · Hybrid retrieval with ReAct Agents and RAGAS Evaluation**

A fully working agentic RAG system built from scratch in Python. Upload any PDF, auto-generate test questions, run three separate ReAct agents with different retrieval strategies, and evaluate them head-to-head using RAGAS metrics — all through a five-tab Gradio interface.

---

## What it does

Three independent ReAct agents answer the same questions from the same document, each using a different retrieval strategy:

| Strategy | How it works |
|---|---|
| **BM25** | Lexical keyword search (TF-IDF based, exact term matching) |
| **Vector (FAISS)** | Semantic search using embeddings — understands meaning and synonyms |
| **Hybrid (RRF)** | Combines BM25 + Vector using Reciprocal Rank Fusion algorithm |

The system then automatically evaluates all three using **RAGAS** across four metrics: faithfulness, answer relevancy, context recall, and context precision.

---

## Results

Evaluated on a 25.1 MB academic PDF (4,152 chunks), 30 test questions generated by GPT-4o-mini:

| Metric | BM25 | Vector (FAISS) | Hybrid (RRF) |
|---|---|---|---|
| Faithfulness | 0.8500 🟢 | 0.6367 🟡 | **0.8806** 🟢 |
| Answer Relevancy | 0.7842 🟡 | 0.6299 🟡 | **0.8874** 🟢 |
| Context Recall | 0.8333 🟢 | 0.6000 🟡 | **0.9000** 🟢 |
| Context Precision | 0.8333 🟢 | 0.6000 🟡 | **0.9000** 🟢 |

**Hybrid retrieval outperforms both single-strategy approaches across all four metrics.**

## Architecture

```
PDF Upload
    │
    ▼
data_preparer.py        ← PDF loading, chunking (RecursiveCharacterTextSplitter)
    │
    ├──▶ FAISS vector index     (OpenAI embeddings)
    ├──▶ BM25 lexical index     (rank_bm25)
    └──▶ Hybrid RRF merger      (Reciprocal Rank Fusion)
              │
              ▼
tool_factory.py         ← Builds retrieval tools for each agent
              │
              ▼
agent_orchestrator.py   ← ReAct agents (LangChain) — one per strategy
              │
              ▼
evaluator.py            ← RAGAS evaluation (faithfulness, relevancy, recall, precision)
              │
              ▼
app.py                  ← Gradio UI (5 tabs: Index → Questions → Benchmark → Eval → Chat)
```

```bash
cd agentic-rag
pip install -r requirements.txt
```

### 2. Set your OpenAI API key

```bash
export OPENAI_API_KEY=your_key_here
```

```bash

```

## Usage — step by step

**Tab 1 — Index PDF**
Upload any PDF. The system splits it into chunks, builds the FAISS vector index, the BM25 lexical index, and initializes all three ReAct agents. Status shows chunk count and index readiness.

**Tab 2 — Generate Test Questions**
GPT-4o-mini reads random chunks and generates question + ground truth pairs. Adjust the slider (2–30 questions). Results saved to `results/test_set.json`.

**Tab 3 — Agent Benchmark**
All three agents answer every question. Results shown side by side in three sub-tabs (BM25 / Vector / Hybrid). Raw outputs saved to `results/raw_*.json`.

**Tab 4 — RAGAS Evaluation**
Automatic evaluation of all three strategies across four RAGAS metrics. Summary comparison table + per-question detail. Saved to `results/ragas_*.csv`.

**Tab 5 — Interactive Q&A**
Chat with any of the three agents in real time. Select retrieval strategy, ask questions, see answers with tool usage and step count.

## Key design decisions

**Why three separate agents instead of one?**
Each agent uses only its own retrieval tools, ensuring clean isolation. Results are directly comparable with no cross-contamination between strategies.

**Why Hybrid + RRF?**
BM25 excels at exact keyword matches; vector search handles semantic similarity. RRF combines both ranked lists without needing to tune score weights — a practical, robust fusion approach. The evaluation confirms it consistently outperforms either strategy alone.

**Why RAGAS?**
RAGAS provides reference-based evaluation without needing human annotation for every metric. Faithfulness catches hallucinations, answer relevancy checks if the agent actually answered the question, and context recall/precision measure retrieval quality independently.

## What would improve it with real data

- Streaming agent responses instead of waiting for full completion
- Persistent vector index (no re-indexing on restart)
- Support for multi-document corpora, not just single PDFs
- Fine-tuned embeddings on domain-specific data for better semantic retrieval
- Asynchronous benchmarking to run all three agents in parallel
